## 1. P0-1 骨穿复核窗口与自身定义矛盾（诱导日历）

**位置**：`demo/build-demo-data.mjs` → `tx.calendar.bands`（张强档案）

**问题**：骨穿高亮带标 `D21–D28`，但标签写「停化疗后 7–14 天」。7+3 的化疗占 D1–D7，停化疗是 D8，
按标签自己的定义窗口应为 **D15–D22**。更直接的证据：`daily` 里 **D15（2026-05-28）真有一条「骨穿复核」记录**。

**为什么是 P0**：患者按这条带判断"什么时候该去做骨穿"。带标晚了一周，会让患者以为还早——
而骨穿窗口本身是判断"要不要二疗程诱导"的关键时点（中国指南：停化疗第 7–14 天复查）。

**为什么探针没抓到**：`probe-aml-m2.mjs` 只数"有几条带"（`dayGrid_demo1_bands: 7`），
不验"带的位置对不对"。**数量对 ≠ 位置对**，与 LESSONS 里「数量对 ≠ 颜色对」是同一类假通过。

**修复**：`{ from: 15, to: 22 }`，标签补明「即 D15–D22」。

**断言**：`scripts/check-calendar-consistency.mjs` C3/C4。变异测试：改回 D21–D28 → C3+C4 双报红。

## 2. P0-2 粒缺发热判定丢掉了「持续 >1 小时」条件

**位置**：`prototypes/v0.2/app.js` 体温录入回调

**原代码**：
```js
if (val >= 38.3 || val >= 38.0) feverFlag(ts, val, v.author); else { ... }
```

**问题**：`v >= 38.3 || v >= 38.0` 在数学上**等价于** `v >= 38.0`。
定义里的「≥38.0℃ **持续超过 1 小时**」被整个丢掉，于是**每一次 38.1℃ 都弹「这是急症信号」**。

**为什么是 P0**：这是把"观察项"升级成"急症"。反复误报会让患者对急症提示脱敏——
真正 38.5℃ 时反而当成又一次误报。同时它也让"文案对（写着持续>1h）但逻辑错"这种最隐蔽的形态成立。

**为什么探针没抓到**：所有断言都在验"弹窗会不会弹"，而它确实弹了。

**修复**：抽出 `classifyTemp(ts, v, priorTemps)`，返回 `none / watch / fever` 三档：
- `≥38.3` → 单次即 `fever`
- `38.0–38.2` → 找同一发热事件里更早的 `≥38.0` 记录，跨度 ≥60 分钟才 `fever`，否则 `watch`（提示 1 小时内复测）
- `<38.0` → `none`
急症弹窗里增加「本次判定依据」一行，把为什么判成急症写清楚。

**断言**：`scripts/check-fever-rule.mjs` 9 条用例（含边界值 38.3、时长 90/30 分钟、37.9 不计入持续、NaN）+ 元断言。
变异测试：改回 `v >= 38.3 || v >= 38.0` → 3 条用例报红。

## 3. P0-3 同一次体温被记进轨道两遍

**位置**：`prototypes/v0.2/app.js` `feverFlag()` 末尾

**问题**：调用方已经 `mem().temps.push({ ts, v, author })`，`feverFlag()` 里**又 push 了一次**。
发热时同一条体温进轨道两遍：曲线出现重复点、`author_role` 计数翻倍（双主体统计失真）。

**为什么是 P0**：双主体（患者本人 / 照护者）是本癌种的核心设计，
"谁记的这条体温"统计错了，等于把 K6 的整个价值抹掉。

**修复**：`feverFlag()` 不再 push，入列由调用方统一负责；注释写明原因。

## 4. P1 primer 承诺了未实现的 APL 线

**位置**：`prototypes/v0.2/primer-data.js`（两处）、`README.md`、`docs/DISEASE-PRIMER.md`

**问题**：原文写「本台把 APL 单列成一条线，日历结构不同」。
但 `PAGES` 里没有 APL 线，两个演示档案都是「AML 非APL」。

**为什么是 P1**：这是**承诺了没做的东西**。患者读到会去找那条线，找不到就怀疑整个台的可信度。
36 号明确允许写「本台尚未整理」，不许假装有。

**修复**：改为「本台当前两个演示档案都是 AML 非APL，7+3 与低强度方案只适用于非APL；APL 线尚未建立，不把 7+3 日历套过去」。

## 5. P2 「半相合已非常成熟」被写成台方判断

**位置**：`prototypes/v0.2/app.js` 供者页副标题

**问题**：原副标题写「"半相合在中国已非常成熟"是可引用出处，不是安慰话」——
句子结构让它读起来像本台的断言。

**来源核实**：`research-notes/medical-constraints.md` §7 第 2 条 + 来源 7.3（黄晓军团队单倍型移植综述，2019）。
**事实本身有出处**，但作为"移植零推荐"的台，不该用自己的口吻说这类可及性判断。

**修复**：改为「半相合的可及性有文献出处（黄晓军团队单倍型移植综述，2019），本台只转述出处、不作安慰话」。
数据里作为「医生答复原文」的引用保留不动——那是医生说的话，不是台说的话。
